# Алгоритмы: фильтры, «пипетка», авто-баланс

> Этапы 0–2 (2026-09-29). Тикеты: T-0007…T-0017, T-0031, T-0032.

## 1. Фильтры (как в Photoshop)

Порядок стека: **Brightness/Contrast → Color Balance → Hue/Saturation → (будущие фильтры) → Opacity**.
Тон идёт первым: Color Balance делит на тени/середины/света по значению канала, поэтому
яркость выставляем до цветового баланса.
Все параметры — числа в «фотошопных» диапазонах, и **формулы откалиброваны по Photoshop 25.6**
(средний ΔE 0.03 по 92 снимкам HALD) — значения ползунков переносимы из PS и обратно.
Законы и замеры — [CALIBRATION.md](CALIBRATION.md).

### 1.1 Color Balance

Три тоновых диапазона × три ползунка, каждый `[-100 … +100]`:

| Диапазон | cyan ↔ red | magenta ↔ green | yellow ↔ blue |
|---|---|---|---|
| shadows | `cb.shadows.cr` | `cb.shadows.mg` | `cb.shadows.yb` |
| midtones | `cb.midtones.cr` | `cb.midtones.mg` | `cb.midtones.yb` |
| highlights | `cb.highlights.cr` | `cb.highlights.mg` | `cb.highlights.yb` |

+ флаг `preserve_luminosity` (по умолчанию `true`, как в PS).

Реализация (T-0007, откалибровано по PS): **«Уровни» по каналам.** У каждого канала точка
чёрного B, белого W и гамма γ, `y = ((x − B)/(W − B))^γ`. Тени двигают B, света — W,
середины — γ; с Preserve Luminosity сдвиг «в цвет» делается уменьшением двух других
каналов, без него — только своим каналом. Ползунки складываются (B, W — сумма, γ —
произведение). Таблица правил — [CALIBRATION.md](CALIBRATION.md#color-balance--уровни-по-каналам).

### 1.2 Hue/Saturation

`hue [-180 … 180]`, `saturation [-100 … 100]`, `lightness [-100 … 100]` (Master).
Как в PS (T-0008): сначала светлота (к чёрному/белому), затем в HSL поворот тона и
насыщенность `S·(1+v)` при v < 0, `S/(1−v)` при v > 0.
Позже — диапазоны по цветам (Reds/Yellows/…) и Colorize (тикет-идея).

### 1.3 Opacity

`opacity [0 … 100]` — смешение результата с оригиналом:
`out = orig + (adj - orig) * opacity/100`. Это «сила» коррекции. Групповое
применение и авто-матчинг выставляют параметры при 100%, пользователь приглушает.

### 1.4 Скорость: запекание в LUT

Brightness/Contrast, Color Balance и Hue/Sat — функции только от цвета пикселя, поэтому весь стек
запекается в 3D LUT `33³` (превью) / `65³` (экспорт) и применяется трилинейно.
Opacity применяется после LUT. Фильтры, зависящие от соседей (резкость, локальные
маски), в будущем пойдут отдельной ступенью после LUT.

### 1.5 Brightness/Contrast

`bc.brightness [-150 … 150]`, `bc.contrast [-50 … 100]` — современный (не Legacy) режим
Photoshop (T-0031, откалибровано): кривая по каналам, не зависит от содержимого кадра;
сначала яркость (в тенях ×e^(0.0063·b), к светам плавно к 1; минус — обратная функция),
затем контраст `x + (c/100)·D(x)` с профилем D из PS. Флаг `legacy` — сдвиг на b/255 и
растяжение вокруг 127/255 с клиппингом.

## 2. «Пипетка»: цветовой профиль изображения (`ColorProfile`) — реализовано (T-0012)

Код — `colormatcher/core/analysis.py`. Снимается **после** собственного стека фото
(для референса это задаёт «от чего отталкиваться» — T-0017).

1. **Выборка** — кадр уменьшается примерно до 12 000 пикселей (все участвуют).
   Работаем в CIE Lab D65 (быстрая линеаризация по таблице, погрешность < 0.05 ΔE).
2. **Почти нейтральные пиксели** — по ним и только по ним оценивается каст (средний цвет
   кадра смещён сюжетом: зелёный лес ≠ зелёный оттенок):
   * пересветы (канал ≥ 0.985) и провалы (L* < 3) исключены;
   * **центр каста — свой у каждого тонового диапазона** (при раздельном тонировании
     тени и света «уезжают» в разные стороны): начальный центр — медиана 10% наименее
     хроматичных пикселей диапазона, затем 2 итерации взвешенного среднего;
   * вес нейтральности `exp(−(|ab − cast_диапазона| / 7)²)`;
   * мягкий потолок абсолютной хромы `exp(−(C/30)²)` — большой ровный цветной фон
     (небо, стена) не выдаёт себя за «нейтраль».
3. **Тоновые диапазоны** — мягкие маски по L* (тени ‾\___, середины _/‾\_, света ___/‾;
   форма как у масок GIMP, a = 0.25, b = 0.333).
4. **Голосование плиток 8×8**: каждая плитка даёт свой каст (относительно кастов тонов);
   плитки, далёкие от взвешенной медианы, получают меньший вес `1/(1+(dev/(2.5·MAD+1))²)`.
   Одна большая машина или стена не перетянет оценку.
5. **Доверие** `confidence = min(1, доля_нейтралей/5%) · exp(−MAD/10)`.

| Поле | Что это |
|---|---|
| `bands[shadows/midtones/highlights]` | `L, a, b` нейтралей диапазона + `mass` (доля веса) |
| `L_p05`, `L_p50`, `L_p95` | Тон: перцентили L* |
| `C_p50`, `C_p90` | Хрома Lab (для справки) |
| `S_p50`, `S_p90` | **Насыщенность Lab `C/√(C²+L²)`** по пикселям с L* > 12 — не зависит от «ключа» сцены (ночь/день), по ней решатель сравнивает насыщенность |
| `neutral_share`, `confidence` | Доля нейтралей, надёжность оценки |

Выборка (`PixelSample`: какие пиксели и с какими весами) фиксируется по исходному
кадру; решатель меняет только их цвета (`measure`) — целевая функция гладкая.

### Усреднение нескольких референсов (T-0013)

`combine(profiles, weights, mode)`: касты диапазонов — взвешенно по `вес × mass × confidence`,
остальное — по весу референса; `mode = median` — взвешенная медиана (устойчива к выбросу).
Без референса — `--to-group-mean`: цель = медиана профилей всей группы.
`ProfileOffset` (L, a, b, множитель насыщенности) — ручное смещение цели (T-0017).

## 3. Авто-баланс: решатель — реализовано (T-0014)

Код — `colormatcher/core/matcher.py`. Решаем **через сам конвейер**: параметры — обычные
ползунки, результат можно докрутить руками и перенести в Photoshop.

```
невязки (единицы Lab):
  каст:          √(α_диап · support) · conf · (a, b)(θ) − (a, b)_ref      support = min(1, mass/0.1)²
  тон:           √0.7 · (L_p05, L_p50, L_p95)(θ) − ref                    если решаем яркость/контраст
  насыщенность:  100 · (S_p50, S_p90)(θ) − ref                            если решаем saturation
  якоря:         √(3 · w) · (Lab_области(θ) − Lab_области_ref)
  регуляризация: √μ/10 · θ  (+ L1 ниже)
```

* **Левенберг–Марквардт**, численный якобиан (шаг 2 пункта), границы — проекцией.
* **Разреженность (≈ L1)**: после обычного решения 2 раунда перевзвешивания
  `√(μ²/100 + λ₁/(|θ|+0.5))·θ`, λ₁ = `sparsity` (0.08). Мелкие ползунки уходят в ноль,
  итог — 5–8 ползунков вместо 9–11, качество то же. Значения округляются до 0.1, |θ| < 1 → 0.
* **Пределы** (`limits`): яркость ±40, контраст ±30, насыщенность ±35, тон ±20, CB ±50.
* **Режимы**: `balance` (9 × CB), **`balance+sat` (по умолчанию)**, `tone+balance+sat`,
  `full` (+ hue). Тон — только по запросу: сравнивать яркость ночной и дневной сцены
  бессмысленно (подтверждено на demo-photos). `touch` — явный список ползунков.
* Все критерии решаются **совместно**. Поэтапная схема (тон → баланс → насыщенность)
  проверена и дала худшее восстановление (ΔE 5.5 против 3.2 на синтетических искажениях).
* Скорость: ~1–1.5 с на фото (≈ 5 мс на оценку); CLI обрабатывает фото параллельно.

## 4. Умная пипетка (T-0015)

1. **Ручные пары-якоря** (`AnchorPair`) — реализовано: прямоугольник на референсе и на
   цели (относительные координаты), цвет области — медиана Lab; входит в решатель с
   большим весом. CLI: `--anchors anchors.json`. Клик-пипетка — в GUI (этап 4).
2. **Самые тёмные / самые светлые области** — сейчас покрываются диапазонами теней и
   светов нейтралей (с исключением пересветов и провалов); отдельные автоякоря —
   если понадобятся после проверки на реальных сериях.
3. **Семантические якоря (опционально, ML)** — T-0016; детали — [ML-ANALYSIS.md](ML-ANALYSIS.md).
4. Оверлей «что пипетка взяла в расчёт» (нейтрали, голоса плиток, якоря) и кисть
   «не учитывать» — в GUI (этап 4).

## 5. Регионы: фильтры по участкам со стыковкой градиентами (продвинутый этап, T-0032)

Пример: небо докрасить отдельно от локации. Сейчас **не реализуем**, но ядро
строим так, чтобы это добавилось без переделки.

* **Модель.** У фото глобальный стек + список `RegionLayer`: мягкая маска `m ∈ [0,1]`,
  свой `AdjustmentStack`, своя opacity.
* **Рендер.** Каждый стек запекается в свой LUT, результат смешивается по маскам:
  `base = LUT_global(img)`, `out = base + Σ_i m_i · opacity_i · (LUT_i(base) − base)`.
  Маски в полном разрешении храним сжатыми, а для превью держим их на прокси.
* **Источники масок.** Линейный/радиальный градиент, кисть, диапазон по
  яркости/цвету, семантика (небо, люди, растительность — модели из T-0016), клик SAM,
  **диапазон глубины** (T-0033).
  Маски комбинируются (∪, ∩, вычитание, инверсия).
* **Стыковка.** Растушёвка краёв (feather) + guided filter по исходному изображению,
  чтобы переход повторял реальные границы (горизонт, листва) без ореолов.
* **Авто-матч по регионам.** Профиль и решатель §3 считаются отдельно для каждого
  класса, если он есть и на референсе, и на цели (небо ↔ небо, локация ↔ локация).

### 5.1 Карта глубины (T-0033)

* Относительная глубина `d ∈ [0,1]` от монокулярной модели (Depth Anything V2, ONNX)
  считается на прокси, апскейлится guided filter по исходнику и кешируется.
* Даёт маску `depth_range [d0, d1]` с растушёвкой — передний/задний план, даль, небо.
* **Матчинг по планам:** `ColorProfile` по ближнему/среднему/дальнему плану. Даль
  обычно холоднее и менее контрастна, поэтому сравнивать план с планом честнее,
  чем кадр целиком.
* Идея: фильтр «дымка» — добавить или убрать воздушную перспективу пропорционально `d`.

Крючки, которые закладываем уже на этапе 1:
1. конвейер принимает «стек + маску», глобальный стек — частный случай с `m ≡ 1`;
2. в схеме `PhotoItem` поле `regions: []` зарезервировано (`schema_version` 1);
3. `ColorProfile` умеет считаться по взвешенной маске (нужно и для семантических якорей §4).

## 6. Проверка качества

* Метрика: ΔE2000 между профилями (по диапазонам) до/после; отчёт `colormatch analyze`.
* Тестовый набор: синтетика (эталон + известный сдвиг ползунков → решатель должен
  вернуть те же значения ±3) и реальные серии фото по сценам (T-0029).

## 5.2 Слои меток по мягким маскам (М2, 2026-09-30)

`render_masked(img, stack, layers, mask)`: G = общий стек(img); out = G + Σ wᵢ·(Lᵢ(G) − G) + w_keep·(img − G),
wᵢ — веса меток (маска uint8 H×W×9, сумма ≤ 1), Lᵢ — слой метки i. Параллельная смесь не зависит от порядка
меток и даёт бесшовные переходы на мягких краях; «не трогать» возвращает исходник. Маска любого разрешения
мягко масштабируется к кадру (INTER_AREA вниз / INTER_LINEAR вверх). Подробности — MASKS-DESIGN.md «Реализация М2».

## 5.3 Авто-баланс по меткам (М3, 2026-09-30)

Общий баланс — как раньше, но без пикселей «не учитывать»/«не трогать» (кадр и референс). Затем для каждой
метки 0…6: статистики области (L* p10/p50/p90; a*, b* тёмной и светлой половины; медиана C*) кадра после общих
правок приводятся к статистикам той же метки референса (нет на рефе — та же геометрия) подбором слоя метки
(B/C, 9 × CB, Saturation) — LM + L1, как у общего решателя (`core/region_match.py`).

Слой «Фон» (T-0082): `+ w_bg·(L_bg(G) − G)`, `w_bg = 1 − Σ всех меток`; без маски — весь кадр. В авто-балансе не участвует.
