# Калибровка фильтров под Photoshop (T-0034)

Цель — **примерная совместимость по цифрам**: одинаковые значения ползунков у нас и в PS
дают близкий результат (цель ΔE2000 < 2 в среднем).

## Идея: HALD вместо фотографий

`hald_8.png` (512×512, 16 бит) содержит **все цвета сетки 64³**. Прогнал её через фильтр в
PS → один PNG = полная таблица «цвет до → цвет после» для этой настройки. По таким
таблицам подгоняются наши формулы. Фото для этого не нужны.

Сгенерировать (если файла нет): `python-embed\python.exe tools\make_calibration.py`

## Автоматически: скрипт для Photoshop (рекомендуется)

1. `python-embed\python.exe tools\make_calibration.py` — создаёт `hald_8.png`, `list.csv`,
   `ps_jobs.jsx` (уже сделано; повторять после изменений списка).
2. Photoshop → **File → Scripts → Browse…** → `tools\ps_calibrate.jsx`.
3. Первый запуск — **пробный** («Да» в первом окне): 5 контрольных файлов в
   `calibration/ps/_trial/`. Затем проверка:
   `python-embed\python.exe tools\compare_ps.py --trial`
   — скрипт покажет таблицу сверки. Колонка «PS Δ» должна быть заметно больше 0,
   «бит» = 16.
4. Если всё в порядке — запуск ещё раз, «Нет» → полный прогон: приоритет 1 (41) или все (92).
   Готовые файлы пропускаются, так что прерванный прогон можно перезапустить.
5. Журнал — `_log.txt` в папке вывода. Открытые документы скрипт не трогает, свой документ
   закрывает без сохранения.

Проверено: синтаксис (Node), генерация заданий, сверщик. В самом Photoshop скрипт
пока не запускался — поэтому пробный прогон первым.

## Вручную: настройка Photoshop (если без скрипта)

1. Открыть `hald_8.png`. Если PS спросит про профиль — **«Использовать встроенный / оставить
   как есть»**, без конвертации. Рабочее пространство RGB — **sRGB IEC61966-2.1**.
2. Режим: **RGB, 16 бит/канал** (Image → Mode → 16 Bits/Channel).
3. Каждая настройка — **корректирующим слоем** над фоном (Layer → New Adjustment Layer),
   все остальные параметры фильтра = 0, режим наложения Normal, непрозрачность 100%
   (кроме строки `op__…`).
4. Сохранить: **File → Save a Copy → PNG** (16 бит, без сжатия с потерями) с именем из
   колонки `file`. **Не** «Export As / Save for Web» — они конвертируют в 8 бит и могут
   менять цвет. Слои сведутся в копии, исходник остаётся.
5. Все PNG — в папку `calibration/ps/`.

## Что снимать

Полный список — `list.csv` (92 строки: колонки `priority; file; group; params; note`).
**Приоритет 1 — 41 файл**: этого хватит для примерной совместимости. Приоритет 2 —
для точности, если будет желание.

Обозначения в `params`:

| Группа | Фильтр PS | Параметры |
|---|---|---|
| `cb` | Color Balance | `shadows/midtones/highlights` × `cr` (Cyan–Red), `mg` (Magenta–Green), `yb` (Yellow–Blue); `pl` = Preserve Luminosity on/off |
| `bc` | Brightness/Contrast, **Use Legacy выкл.** | `b` — Brightness, `c` — Contrast |
| `bcl` | Brightness/Contrast, **Use Legacy вкл.** | то же |
| `hs` | Hue/Saturation, Master, Colorize выкл. | `h` — Hue, `s` — Saturation, `l` — Lightness |
| `op` | Color Balance (как первое сочетание), слой 50% | проверка смешения |

Шаги значений:

| Параметр | Приоритет 1 | Приоритет 2 (добавочно) |
|---|---|---|
| Color Balance, каждый из 9 ползунков, PL вкл. | ±100 | ±50 |
| Color Balance, PL выкл. | cr ±100 во всех трёх диапазонах | yb +100 |
| Brightness (Contrast 0) | ±50, ±150 | ±25, ±100 |
| Contrast (Brightness 0) | −50, +50, +100 | −25, +25, +75 |
| Brightness + Contrast | (+50, +50) | (−50, +50), (+100, −30), Legacy ×4 |
| Hue | +90 | −90, ±30, 180 |
| Saturation | ±50, ±100 | ±25, ±75 |
| Lightness | ±50 | ±25, ±75, ±100 |
| Сочетания / opacity | CB-сочетание, op 50% | CB-сочетание с PL выкл., 2 сочетания HS |

## Дополнительно: адаптивен ли Brightness/Contrast в PS

Есть подозрение, что современный (не Legacy) Brightness/Contrast в PS подстраивается под
содержимое картинки. Проверка — два **реальных** фото (одно тёмное, одно светлое) с
одной и той же настройкой **Brightness +50, Contrast +50**, сохранить как
`adapt__dark.png`, `adapt__light.png` + их исходники рядом (`adapt__dark_src.png`,
`adapt__light_src.png`) в `calibration/ps/`. Если PS адаптивен — HALD его не поймает,
и формулу придётся строить иначе.
